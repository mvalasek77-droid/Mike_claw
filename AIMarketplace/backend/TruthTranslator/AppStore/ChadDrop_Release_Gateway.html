Signing, In Plain English

Signing is Apple proving that the app came from your Apple Developer account. The app cannot go to the App Store until Apple knows which developer team owns com.chaddrop.app.

YouJoin Apple Developer Program and sign in.
XcodeUses your team to create certificates and profiles.
ChadDropBundle ID is com.chaddrop.app.
ArchiveA signed release build is created.
AppleAccepts the build for TestFlight/App Review.
What you do in Xcode
  1. Open TruthTranslator/TruthTranslator.xcodeproj.
  2. In the Mac menu bar, choose Xcode -> Settings -> Accounts.
  3. Press the plus button, sign in with your Apple ID, and finish two-factor authentication.
  4. Click the ChadDrop project, select the TruthTranslator target, then open Signing & Capabilities.
  5. Turn on Automatically manage signing.
  6. Choose your Apple Developer Team.
  7. If Xcode shows a red error, read the exact message. Most errors mean the Apple account is not enrolled, the agreement is not accepted, or the bundle ID is already taken.

CodeGenie can run the build after this, but it cannot safely type your Apple password, pay for the developer account, or approve two-factor codes.

Avoid Local Signing With Xcode Cloud

This is the cleaner path when you do not want to fix signing on this Mac. CodeGenie prepares the repo; Apple builds, signs, and sends the app to TestFlight after you approve App Store Connect and GitHub access.

App recordCreate ChadDrop in App Store Connect.
Repo accessGrant Apple access to the GitHub repo.
WorkflowUse scheme TruthTranslator.
Cloud buildApple runs tests and archive.
TestFlightInstall internally before App Review.
Exact setup for non-coders
  1. Open App Store Connect, go to My Apps, press +, then choose New App.
  2. Use iOS, name ChadDrop, bundle ID com.chaddrop.app, and SKU CHADDROP-IOS-1.
  3. Open TruthTranslator/TruthTranslator.xcodeproj in Xcode.
  4. Open the Report Navigator, choose the Cloud tab, then press Get Started.
  5. Grant App Store Connect access to the GitHub repo when Apple asks.
  6. Create a workflow named Build & Test.
  7. Choose the branch you want to ship from.
  8. Add a Test action for scheme TruthTranslator on recommended iPhone simulators.
  9. Add an Archive action for scheme TruthTranslator and send the result to TestFlight Internal Testing.
  10. Save the workflow. Apple starts the first build automatically.

CodeGenie added TruthTranslator/ci_scripts. Apple uses those scripts during Xcode Cloud builds. You still approve Apple ID login, GitHub access, paid account steps, and final App Review submission.

AI Choice

ChadDrop works offline right now. If you want real AI-generated answers, use a server proxy. Never put an OpenAI key inside the iPhone app.

Decision

Pick one before submitting.

Ship offline first

Fastest path. Privacy answers are simpler. The app uses the built-in rule engine.

Ship with AI proxy

Deploy the included Cloudflare Worker, store the OpenAI key as a server secret, then set AI_PROXY_URL.

If using AI, what CodeGenie can do
  1. Create or update the proxy code in Proxy/openai-worker.js.
  2. Open Cloudflare Workers for your login.
  3. Run Wrangler deploy after you approve Cloudflare login prompts.
  4. Set the app's AI_PROXY_URL after you provide the public Worker URL.
  5. Update App Store privacy answers to say User Content is processed to provide app functionality.
